# 多想想

一个问题可以问模型一次，也可以问很多次。每个答案都有它的代价，而如果好答案和坏答案分得清，再试一次就可能值得花这个钱。

## 算账

<RecipeFor id="reckoning_dataset" />

<ItemLink id="reckoning_dataset" />里是一行行相加的数，写出每一步的累计：

```
> 12,7,30,5
= 19 49 54
```

最后一个数就是答案。每一步都能单独检查，谁都能查，除了算术什么也不用，所以它才值得多想：错的答案能被抓住，再试一个。**算账**测试看练习中从未出现的和里，每一步都对的占多少，通过的门槛是 70%；多试几个答案，可能帮助模型达到它。

## 一个问题的答案数

在[模型服务器](deployment.md)里放一枚<ItemLink id="kv_cache" />，第三个按钮就决定它对一条指令或一道算账写多少个答案。它只留一个：算账留每一步都查得过的；指令留能在沙盒里运行的那些当中最多的结果，面板最后一格放了裁判的话，就留裁判打分最高的。如果没有答案查得过，就留最常见的。其他问题只问一次。

每个答案都要付钱。它们只读一次问题，然后一起往下写，但尝试越多，留给其他问题的容量就越少。服务器的界面显示回答速率和每项测试现在的成绩，提问的一方都按这些成绩办事。增加思考量，可能改变它能通过哪些测试。

模型可能反复犯同一个错，所以最常见的答案未必正确。算术检查可以把错的和排除，不管它出现过多少次。

指令就不一样了：一个程序运行时不失败，仍然可能没做到原意。取最常见的，可能会选中它，错过更好的程序。服务器对指令想得更久，可能反而过不了程序测试，它的界面会说明。

## 给每一步打分

[调校台](tuning.md)设为验证、检查*算账*时，按每次尝试对了多少步来打分，而不只看最后对不对，所以四步对三步的尝试，比一步都不对的更值钱。除此之外没有东西告诉它答案。奖励线显示检查器偏向什么；保存后的模型在算账测试上的成绩，显示它会怎样处理练习没给过的算式。

## 化验

炉温稳在那一档的熔炼会给出一份化验，一行要相加的数。冶炼炉的控制器按服务器提供的形式通过了[精准](tuning.md)和算账，它就把化验交给这个控制器。每一步都对，这次熔炼一份矿石就出九个锭，而不是六个。服务器为此花了多少，在它的界面上归在冶炼炉名下。
